# FastSymbolicGP V1.2.3 Acceptance Report

## Release identity

- Version: **1.2.3**
- Release theme: **Ultra-Fast Quality-Preserving Core**
- Primary goal: reduce runtime of ordinary fused-Numba symbolic regression without buying speed by weakening the search.

## Why V1.2.3 exists

The user-side V1.2.1 benchmark on scikit-learn Diabetes used 500 individuals × 100 generations and reported **22.879 s**, test **R² = 0.4520**, and a profile dominated by Python-side variation. V1.2.2 reduced several variation costs but changed tournament sampling to a with-replacement bulk approximation. V1.2.3 deliberately restores true without-replacement tournament pressure while optimizing the evaluator and tournament winner path.

## Core changes certified

1. **Exact single-pass fused squared-error training loss**
   - For MSE, RMSE and R²-loss, the first fused training pass already accumulates all sufficient statistics needed after affine scaling.
   - The second symbolic-expression pass over the training split is therefore eliminated.
   - MAE and Huber remain exact and retain their residual-wise second pass.

2. **Faster postfix population packing**
   - NumPy concatenation/cumulative offsets replace per-node Python list expansion.

3. **Cheaper Numba compile-cache lookup**
   - Immutable root identity is used for the ephemeral compiled-postfix cache.
   - Constant optimizers invalidate the cache when program values change.

4. **Quality-preserving fast tournament**
   - Tournament sampling remains without replacement.
   - Population ordering is exploited so winner selection avoids candidate-list construction and unnecessary repeated comparisons.
   - The V1.2.3 profile reports `without_replacement_exact_fast`.

5. **Fast unconstrained fused path**
   - When no scientific/unit constraints are active, the fused evaluator does not call the general constraint machinery for every candidate.

## Quality gate outcome

V1.2.3 does **not** use the faster bounded/order-statistic experimental variation paths tested during development because those paths reduced benchmark R². They were rejected before release. The certified implementation explicitly prioritizes preserving useful tournament search pressure while accelerating the exact fused evaluator and hot-path bookkeeping.

## Known limitations

- CPU-first; no CUDA/GPU evaluator in this release.
- Exact without-replacement tournament remains a significant Python-side cost at very large populations/generation counts.
- MAE and Huber need a second training residual pass and therefore do not receive the full single-pass squared-error speedup.
- Performance depends strongly on expression size, duplicate reuse, primitive set, CPU, Numba version and thread configuration.
- Protected operators can create algebraically unusual but numerically defined expressions; simplification/export should preserve protected semantics.

## Release decision

**PASS.** V1.2.3 is the preferred V1.2 release for ordinary fast symbolic regression when result quality must not be traded away merely to improve benchmark time.
