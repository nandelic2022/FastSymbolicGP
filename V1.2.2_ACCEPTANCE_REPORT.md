# FastSymbolicGP V1.2.2 Acceptance Report

## Release identity

- Version: **1.2.2**
- Release theme: **Fast Variation Engine Hotfix**
- Python: >= 3.11
- Fast path: Numba + fused regression + scalar optimization + standard tournament variation

## Why this release exists

A real 500-population × 100-generation Diabetes benchmark on V1.2.1 showed that the numerical evaluator was already fast, while Python-side variation dominated runtime. The user-side profile showed approximately 4.06 s in evaluation and 17.76 s in variation. V1.2.2 therefore targets parent selection, tree copying, structural bookkeeping, admissibility checking and evolution snapshots rather than changing the fitness kernel.

## Main hot-path changes

1. Standard tournament selection no longer copies `list(pop)` for every parent selection.
2. The common scalar/tournament path uses bulk tournament schedules.
3. Crossover and mutation use persistent-tree structural sharing instead of deep-copying whole parent trees.
4. `Program.paths()` is cached as an immutable tuple.
5. Program size/depth are calculated together in a single traversal and cached.
6. Ordinary non-typed/non-hard-constrained runs use a direct depth/node admissibility fast path.
7. Evolution-state snapshots use cheap immutable program clones for internal populations and archives.
8. Internal DataFrame → NumPy reporting no longer emits the sklearn feature-name warning.
9. The profile exposes `variation_engine` and `tournament_sampling`.

## Regression testing

The patched functional code passed the complete historical V1.0–V1.2.1 test matrix module-by-module before the metadata/version bump: **104/104 tests passed**.

After the 1.2.2 metadata bump, all version-bearing compatibility modules were rerun successfully, and the dedicated V1.2.2 tests passed **4/4**. The final wheel also passed the built-in diagnostic self-test for regression, classification, sklearn cloning and fused regression.

A single-process `pytest` invocation can stall in this container after repeated Numba/sklearn thread-pool initialization across modules; isolated module runs are clean. This is a test-runtime interaction, not a reproduced estimator deadlock.

## Clean-wheel benchmark

The final `fastsymbolicgp-1.2.2-py3-none-any.whl` was installed into an isolated target directory outside the source tree and tested on the scikit-learn Diabetes dataset after Numba warm-up.

Configuration:

- population: 500
- generations: 100
- operators: add/sub/mul/div
- max depth: 8
- max nodes: 60
- RMSE + linear scaling
- validation fraction: 0.20
- evaluation backend: Numba
- fitness engine: fused
- optimization: scalar
- semantic diversity: off
- age management: off
- memetic search: off
- n_jobs: -1
- random_state: 42

Observed on the bundled runtime:

- runtime: **~11.13 s**
- actual program evaluations: **42,037**
- programs/s: **~3,781**
- evaluation stage: **~5.99 s**
- variation stage: **~4.49 s**
- state snapshot: **~0.003 s**
- variation engine: `fast_shared_tree_bulk_tournament`
- tournament sampling: `with_replacement_bulk`
- backend: `numba`
- fitness engine: `fused`

These timings are workload-, CPU-, Python-, Numba- and OS-specific and are not a universal speed claim.

## Same-runtime V1.2.1 → V1.2.2 development comparison

Using the same 500-population, four-operator Diabetes configuration for 50 generations in this runtime:

- canonical V1.2.1 source: **~11.26 s**
- V1.2.2 patched source: **~5.15 s**

This is approximately a **2.2×** speedup for that specific same-runtime comparison.

## Intentional semantic note

The new bulk fast tournament path samples contestants **with replacement**, a standard tournament-selection variant. Typed/unit-enforced or hard-scientific-constraint paths continue to use the generic safe variation machinery.

## Status

**PASS — V1.2.2 is suitable as the preferred fast V1.2 release for ordinary symbolic regression/classification workloads.**
